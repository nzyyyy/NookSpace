# 0001 — 统一 Item 模型

**状态**：已接受（2025-08）

## 背景

NookSpace 需要管理笔记、文件、链接三类内容，还要统一做收藏、最近、搜索、回收站。

## 决策

所有内容都是 `items` 表中的一条 **Item**，用 `type` 列区分（`note` / `file` / `link`）。
类型特有字段放在可空列（`content`、`url`、`stored_path`、`size`、`mime`）+ `meta` JSON 列。

## 备选

- **类型分离**（notes / files / links 三张表）：schema 更"正统"，但列表、搜索、
  收藏、回收站全部需要多态查询，复杂度翻倍，与 MVP 目标相悖。

## 后果

- 所有组织维度只实现一遍，任何类型天然支持收藏/标签/集合/搜索。
- 类型特有字段可选，靠领域约定 + 前端类型而非数据库强制。
- 若未来类型差异过大（例如音频波形数据），可加独立扩展表挂到 item_id 下。
